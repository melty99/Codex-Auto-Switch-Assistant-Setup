# Codex Auto Switch Assistant

The app has Home and Settings tabs and a persistent Chinese/English toggle. Quick setup detects local Codex Desktop, CLI, data directories, CC Switch, Python and Node paths; it validates compatible config homes, preserves disabled modes, and never reads tokens. Missing paths can be selected manually. The manifest display name is Codex Auto Switch Assistant; the stable plugin ID remains codex-quota-guard for existing installations.

Use the bundled native settings window to adjust thresholds, enable or disable automatic management, inspect paused tasks, or cancel their automatic recovery.

Home also has Refresh CC Switch for quota query errors after a VPN change. It refreshes every managed account, retries failed queries once, and reports partial failure or contention with a switch plan. It does not activate accounts, quit Codex, or change networking. Wait for the VPN connection to stabilize before retrying; do not substitute forced process termination for this read-only refresh.

The adaptive-polling section in Settings edits five-hour quota bands and polling intervals (by default ≥20%:180s, 10–20%:60s, <10%:30s). The pause threshold is independent and user-configurable; read saved settings instead of assuming the original 1% default. Waiting and recovery checks use the short interval. With automatic switching enabled, a threshold-triggered switch persists confirmed pauses, gracefully exits Codex before activating the prechecked account, and immediately reopens the desktop without an extra post-switch quota gate. Regular monitoring still guards task resumption. Do not trigger this lifecycle merely to test the settings. The tasks section in Home also provides a right-click per-chat queue; only enqueue instructions explicitly supplied by the user and do not treat a quota interruption as task completion.

- Run `scripts/open-settings.cmd` from this plugin's root to open settings (via `cmd.exe /d /c` if needed). Resolve the root two directories above this SKILL.md. The launcher uses the bundled Codex Python runtime without installing software or changing PowerShell execution policy. Startup failures show a dialog with an error log path.
- Read the guard's `status.json` under `Documents/Codex/QuotaGuard` for a status question; show quota freshness and connection state. Do not print authentication files.
- Background monitoring runs outside the model. Do not add a polling loop to each chat or claim the model can wake itself when quota is exhausted.
- On a guard-generated recovery message, inspect the most recent tool result and files, then continue the original unfinished task. Check uncertain external side effects before repeating them. Preserve the user's scope, approvals, and manual stops.
- A plugin disable is authoritative. Do not re-enable the plugin or restart automatic work unless requested. The settings window also has a separate pause switch.
- If the desktop IPC protocol is incompatible or the action outcome is unknown, report that state. Do not fall back to blind keystrokes, killing the app, editing Codex databases, or replaying all conversations.

The plugin monitors local desktop chats. The settings window's manual account-switch button refreshes other CC Switch accounts and selects an eligible one through CC Switch's own accessible controls. Manual and automatic switching share the same persist-pause, confirmed desktop exit, account activation and immediate Windows package activation lifecycle. Confirm the returned process ID before reporting launch success; regular monitoring still verifies quota before resuming tasks. Manual switching requires the plugin, management and auto-resume toggles, but not the automatic-switch toggle. When no tasks are running, manual switching reopens the desktop without sending resume messages. Never activate an account while the desktop is still open; an uncertain exit or activation requires review. It requires the supported CC Switch version and Codex provider page described in the README. Manual and optional automatic switching share the saved quota-score or custom-priority policy. Automatic switching is disabled by default and requires its explicit settings toggle; respect all plugin/management disables. The account section in Home reads CC Switch account metadata and provides reordering without exposing credentials. Do not click the button just to open settings or inspect status. Do not replay an earlier completed manual switch after upgrading.

The waiting section in Settings controls the all-accounts-insufficient workflow: select the earliest five-hour reset with weekly quota available, save confirmed paused chats, quit the supported desktop gracefully, and monitor quotas independently. Natural resets retain a five-minute buffer; a clear early quota recovery can reopen the planned original chats after two qualifying samples. A per-plan Windows task checks that the guard is running every minute while waiting. Do not trigger real account switches or desktop exit merely to test settings. Read `reset-wait.json` and `account-observations.json` for wait status without exposing credentials. User cancellation or disabling relevant management switches stops the plan; restarting the guard preserves it. Only plan-owned original chats are reopened automatically. Other chats without a live desktop owner wait for the user to open them. Full live exhaustion-to-recovery testing remains unverified; see the README for version limits and recovery boundaries.

The account list displays both remaining quota windows with cache labels; display reads refresh CC Switch but are not sufficient evidence for switching. Waiting settings save immediately. `wait_auto_resume` (default true) controls reopening/resuming a reset-wait plan: turning it off keeps the plan and monitoring, unlike the removed cancel-plan button. Re-enabling checks quota again and never revives cancelled records. `wait_for_reset=false` still cancels wait plans; ordinary prequalified-account switches are unaffected by `wait_auto_resume`. All interface fonts use Microsoft YaHei.

Monitoring is hosted by a per-user Windows scheduled task outside Codex's process job. Shutdown identity (PID and creation time) is persisted before quitting; recovery after a guard restart requires proof of exit and no replacement desktop. For a pre-switch exit review, an explicit manual-switch click can validate the current account and open desktop, archive the failed plan, and create a fresh request. Never clear an uncertain activation for an automatic retry.
